# s03-l03: Understanding the Agent Loop

Explain the observe, reason, act, receive-feedback and stop cycle used by tool-calling agents.

## Run and inspect

From repository root: `python3 examples/stages02-04/foundations.py`. On Windows use `py -3` when appropriate. Inspect `agent_loop` in `examples/stages02-04/foundations.py` (SDK class in `sdk_adapter.py`).

Inspect messages before the first model call, after the assistant tool request and after the tool result. Match the tool_call_id exactly. Force max_calls=1 on a tool-request fixture.

## Deliverable

Submit your changed experiment, redacted actual output, and a short explanation of what remains untested. Never include credentials. Reset by deleting only your own temporary output/virtual environment; do not delete repository fixtures.

## Acceptance rubric

The tool result is returned as role=tool with matching identity. The one-call cap stops with human decision required, rather than silently producing an unverified answer.

Run `python3 -m unittest discover -s tests -p test_stages_02_04.py -v`. Fixtures are labelled synthetic; live vendor/app setup and screenshots require separate actual execution. See `solutions/s03/s03-l03.md` after attempting the task.
