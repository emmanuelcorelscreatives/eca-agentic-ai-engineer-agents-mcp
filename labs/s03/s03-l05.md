## Source-aligned semantic repair

The complete professional-profile/contact pattern exercises now live in `examples/stages02-04/stage03_patterns.py`. These supplement the earlier stock/uppercase minimal examples and supersede them where the workbook requires the same contact task, typed state or provenance. Data and model transports are synthetic unless a separate authorized actual run is explicitly recorded. Newly authored code/tests have not yet been executed; the coordinator's finite central QA owns execution. No generic test receipt is production or visual approval.

`route_request(request, RequestState)` implements an explicit professional_information/contact_capture/unsupported/human_review taxonomy. Profile field enum is name/role/skills. Contact action needs an exact valid email and matching application consent; an application hold overrides otherwise valid requests. Unknown category, unsupported field, mixed/extra fields or malformed input cannot trigger storage. The category input is a validated structured classification, not a claim of natural-language understanding. Ambiguous classifications fall back safely; a model classifier would need a separately tested boundary.
