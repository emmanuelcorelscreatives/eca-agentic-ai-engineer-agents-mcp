# s03-l08: Evaluator-Optimizer Loops

Add an evaluator that reviews an output and directs controlled revisions until requirements are met.

## Run and inspect

From repository root: `python3 examples/stages02-04/foundations.py`. On Windows use `py -3` when appropriate. Inspect `optimize, evaluation` in `examples/stages02-04/foundations.py` (SDK class in `sdk_adapter.py`).

Use an evaluator that always returns score=1/pass=false and run max_revisions=2. Then use a passing score=4 verdict. Inspect all drafts/reasons and the final human-review status.

## Deliverable

Submit your changed experiment, redacted actual output, and a short explanation of what remains untested. Never include credentials. Reset by deleting only your own temporary output/virtual environment; do not delete repository fixtures.

## Acceptance rubric

Failure produces three evaluations and two revisions, then needs_human_review. A first passing verdict stops immediately. This cap does not imply that a model evaluator is ground truth.

Run `python3 -m unittest discover -s tests -p test_stages_02_04.py -v`. Fixtures are labelled synthetic; live vendor/app setup and screenshots require separate actual execution. See `solutions/s03/s03-l08.md` after attempting the task.
