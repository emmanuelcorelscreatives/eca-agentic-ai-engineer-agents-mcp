## Current authored tool workflow and generated-response boundary

The actual workflow now executes `lookupTicket.execute`, then
`findArticles.execute`, then a deterministic bounded source-review step and
a final evidence validator. It does not call `localEvidence` as a workflow
shortcut. Exact tool-return schemas are parsed before continuing. Wrong ticket
fields, cross-product articles and altered article text fail source binding.
Missing evidence enters the explicit human-review-required branch; no message
is sent and no model reviewer is simulated. Retain genuine workflow step/error
records during central execution.

`generateValidatedTriage` is the actual model invocation boundary: it requires
explicit call approval, Academy resource/thread IDs, uses real Agent.generate
with native Memory and structuredOutput, then parses the terminal object through
the evidence schema and checks the exact retrieved ticket and citations. It
returns the raw SDK response for evidence. Schema/citation validation does not
prove every free-text claim or real model recall.
