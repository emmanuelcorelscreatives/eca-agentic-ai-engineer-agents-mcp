# s06-l07: Validate Tool Inputs and Outputs

Objective: Protect tool execution with typed parameters, structured returns and application-level validation.

Use Python 3.10 or newer. All data in `data/s06-catalogue.json` and `data/s07-support-cases.json` is synthetic Academy teaching data. No customer records or live provider results are included.

## Work

Mutate a valid fixture with an extra field, missing title, invalid level and non-list prerequisites. Confirm local parsing rejects each. Inspect CourseAnswer extra=forbid and the course_id pattern; compare schema validation with factual validation.

Implementation to inspect: `examples/stages06-07/workflows.py` and `examples/stages06-07/sdk_adapter.py`, symbols `Course.parse / CourseAnswer`.

## Run and check

From the repository root:

```sh
python3 -m unittest discover -s tests -p test_stages_06_07.py -v
python3 examples/stages06-07/workflows.py --stage 6
```

Relevant acceptance check: `test_schema_rejects_invalid_extra_and_level`. Optional actual SDK construction/storage tests require `examples/stages06-07/requirements.txt`; without it those checks are explicitly skipped. Inspect the test assertions, make one deliberate regression and confirm the matching check fails before restoring it.

## Added tool-return boundary

Use the catalogue fixture, not the separate arithmetic companion. Inspect
`CatalogueToolResult`, `CatalogueRecord` and `validated_catalogue_result` in
`sdk_adapter.py`: the decorated tool invokes this boundary before returning to
the SDK. Test the known ECA-101 record and the unknown ECA-999 variant. Then
mutate the **return** to use a string Boolean, missing/extra field, null known
record, malformed prerequisites, invented but well-typed title, or ECA-201's record
for an ECA-101 request. Each must fail instead of reaching the model as a fact.
Explain why final-answer validation alone did not protect this tool-return boundary.

New authored check: `test_structured_tool_return_validates_shape_variants_and_current_facts`
in `tests/test_stage06_07_semantic_repairs.py`; central execution is pending.
