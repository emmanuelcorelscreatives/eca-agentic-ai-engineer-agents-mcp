# s18-l09: Approve, Edit or Reject Agent Actions

Build decision controls that let users approve, modify or cancel a proposed action.

## Coherent course case and actual source

Read `examples/s18/native_durability.py` → `sqlite_graph(mode="review")`. These are source references, not evidence that the new feature has passed runtime verification.

## Practical exercise

Approve one proposal, reject another, and edit a third; try the old digest after editing before sending a fresh approval.

## Acceptance and reference reasoning

Edit is a new proposal, not immediate permission to execute changed text. The graph validates the edited payload, creates its changed digest and interrupts again. The old approval is stale; only a fresh exact approval of the replacement can dispatch it. Reject dispatches nothing and preserves the decision history.

## Verify your result

local validation must exercise all three controls, edited re-interruption and stale old approval rejection through native execution. Do not use the older custom immediate-edit dispatch as the taught native contract.

Follow this lesson's acceptance criteria and record your own actual results. A fixture or scripted model is not a live provider response; a passing helper test does not establish a complete integrated application.

The replacement proposal must also have a NEW `action_id`; retaining the old action identity is rejected. The reviewer input is exactly the labeled `academy-fixture-reviewer` fixture, not model-generated authority.
