# s18-l09: Approve, Edit or Reject Agent Actions

Build decision controls that let users approve, modify or cancel a proposed action.

## Actual repository implementation

Read `examples/s18/durable_sessions.py` → `Sessions.decide`. Run from repository root:

```sh
python -m unittest discover -s tests -p test_stages16_19.py -v
```

## Exercise

Exercise approve, edit, reject and stale repeated approval.

## Acceptance and evidence

Approve stores the exact reviewed mock payload once; edit validates the modified payload; reject stores no delivery. A repeated committed ID can only reuse the identical payload hash.

Retain the command, actual output and relevant negative-case evidence. Fixture runs are explicitly deterministic, not provider observations. Capture only genuine application/terminal views from the tested code.

## Remaining recording gate

These are local mock effects; external sends need real provider idempotency and authorization.
