# s18-l05: Fork Agent State from Earlier Checkpoints

Start an alternative execution path from a selected historical state.

## Coherent course case and actual source

Read `examples/s18/native_durability.py` → `sqlite_graph`. These are source references, not evidence that the new feature has passed runtime verification.

## Practical exercise

Use graph.update_state at a selected historical checkpoint, retain the returned branch config and resume that branch to its alternative outcome.

## Acceptance and reference reasoning

A genuine fork changes an explicit state field, obtains new checkpoint identity and continues from that branch. The original checkpoint and its continuation remain unchanged. Merely creating a fork without continuing it does not demonstrate the complete alternative execution.
