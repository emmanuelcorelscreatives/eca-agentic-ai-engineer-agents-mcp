Carry out approved navigation, extraction and interaction steps through Playwright.

## Coherent practical case

An Academy-owned local workshop/catalog research task, with synthetic draft-form interactions only. Keep planning, browser observations, source-attributed findings, evaluation, approvals, artifacts and user-facing progress in one persisted session.

## Source map

Project root: `projects/06-browser-sidekick`. Baseline source anchors: `sidekick.py: PlaywrightBrowser; sandbox_server.py: Sandbox`. Read the current integrated module listed in the stage workbook as well; baseline helpers alone do not prove full application integration.

## Exercise

Navigate the local catalog, inspect a detail view, extract visible values and prepare a bounded approved interaction through the intended Playwright executor.

## Acceptance and reasoning

Own the browser/context/page and close them on failure. Use semantic locators, state waits and bounded timeouts. Keep the planned step and observation linked. The earlier urllib sandbox POST test is a real HTTP test but is not proof that a Playwright browser performed an interaction. Sensitive interactions wait for exact approval.

## Verify your result

Record the command, dependency versions and actual result when you run this exercise. Expected results are not observations. Offline fixtures, SDK construction, model responses, browser interactions and Docker execution verify different things; report skips and failures honestly.
