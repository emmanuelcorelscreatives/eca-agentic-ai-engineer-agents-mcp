Analyze execution paths, tool success, user interventions, latency and completion quality.

## Coherent practical case

An Academy-owned local workshop/catalog research task, with synthetic draft-form interactions only. Keep planning, browser observations, source-attributed findings, evaluation, approvals, artifacts and user-facing progress in one persisted session.

## Source map

Project root: `projects/06-browser-sidekick`. Baseline source anchors: `advanced.py: sidekick_event records, SessionController.snapshot`. Read the current integrated module listed in the stage workbook as well; baseline helpers alone do not prove full application integration.

## Exercise

Analyze one complete run with model/planner, browser/tool, specialist, evaluator and user-decision events. Identify latency, evidence quality and the actual completion decision.

## Acceptance and reasoning

Timing and status must come from the actual run. Keep controlled failures, user interventions and unresolved gaps. Distinguish local traces from hosted traces; no fabricated throughput/quality benchmarks. A constructor or disconnected helper result cannot prove full run latency.

## Verify your result

Record the command, dependency versions and actual result when you run this exercise. Expected results are not observations. Offline fixtures, SDK construction, model responses, browser interactions and Docker execution verify different things; report skips and failures honestly.
