# s04-l06: Use a Model as an Evaluator

Create a structured evaluation prompt that compares outputs against explicit scoring criteria.

## Run and inspect

From repository root: `python3 examples/stages02-04/foundations.py`. On Windows use `py -3` when appropriate. Inspect `evaluation, optimize, model_evaluate` in `examples/stages02-04/foundations.py` (SDK class in `sdk_adapter.py`).

Write a rubric for citation presence, correctness and relevance; ask an optional live evaluator for exactly score/pass/reason JSON. Test malformed fields and a score that contradicts the pass threshold with offline inputs.

## Deliverable

Submit your changed experiment, redacted actual output, and a short explanation of what remains untested. Never include credentials. Reset by deleting only your own temporary output/virtual environment; do not delete repository fixtures.

## Acceptance rubric

Only scores 0–5 and boolean pass with threshold >=4 are accepted. A schema-valid evaluator can still be mistaken; use labelled human cases/calibration rather than treating PASS as certainty.

Run `python3 -m unittest discover -s tests -p test_stages_02_04.py -v`. Fixtures are labelled synthetic; live vendor/app setup and screenshots require separate actual execution. See `solutions/s04/s04-l06.md` after attempting the task.
