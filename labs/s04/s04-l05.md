# s04-l05: Select Models by Capability, Cost, Speed and Reliability

Develop a repeatable model-selection process based on the requirements of a specific agent task.

## Run and inspect

From repository root: `python3 examples/stages02-04/foundations.py`. On Windows use `py -3` when appropriate. Inspect `select_model` in `examples/stages02-04/foundations.py` (SDK class in `sdk_adapter.py`).

Load the labelled synthetic model observations, apply quality>=4 and latency<=5 seconds, choose the lowest illustrative cost among eligible rows, and test an impossible quality threshold. Replace fixtures with your measured observations for a real selection.

Submit your changed experiment, redacted actual output, and a short explanation of what remains untested. Never include credentials. Reset by deleting only your own temporary output/virtual environment; do not delete repository fixtures.

Run `python3 -m unittest discover -s tests -p test_stages_02_04.py -v`. Fixtures are labelled synthetic; live vendor/app setup and screenshots require separate actual execution. See `solutions/s04/s04-l05.md` after attempting the task.

## Predeclared task-specific selection worksheet

Use `TaskRubric`, `Measurement` and `weighted_model_worksheet` in `stage04_selection.py`. Before observing results, declare three actual course task IDs (for example profile extraction, grounded summary and allowed tool request), each objective, declared-on date, required capabilities, minimum quality, maximum average latency in seconds, maximum average cost **per attempt** with explicit currency/unit, metric weights summing to1 and a positive aggregate task weight. These three tasks are the existing practical's comparison; they are not a universal benchmark quota.

An illustrative rubric is quality=.4, speed=.2, cost=.2, reliability=.2; task quality uses an explicit 0–5 human/task rubric. Every candidate/task row records model ID, observed-on date, quality score, average latency seconds, average cost per attempt and currency/unit, successful/attempted requests, observed capability names and whether data is synthetic. Keep dated pricing/source and raw actual observations with the worksheet. Reliability is successful/attempted; a single successful canned answer is not measured reliability.

Utilities: quality/5; speed=max(0,1-latency/ceiling); cost=max(0,1-cost/ceiling); reliability=successes/attempts. Multiply by the **predeclared** metric weights; aggregate task scores by declared task weights. Required capability/quality/cost/speed thresholds control eligibility. Missing rows/measurements remain explicit missing with no score or recommendation. Do not fill missing values with zero or crown the only measured candidate in a partial comparison. A tie is reported, not hidden. Units must match or be converted explicitly; observations cannot predate their declared rubric. Example test measurements are synthetic and yield an exercise ranking only, never a real vendor winner.
