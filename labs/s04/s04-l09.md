# s04-l09: Tool Schemas, Arguments, Results and Validation

Design clear tool contracts with typed parameters, validated results and understandable error messages.

## Run and inspect

From repository root: `python3 examples/stages02-04/foundations.py`. On Windows use `py -3` when appropriate. Inspect `TOOLS, execute_tool` in `examples/stages02-04/foundations.py` (SDK class in `sdk_adapter.py`).

Send {sku:BOOK}, unknown SKU, extra keys and malformed JSON. Add a new read-only lookup only after specifying allowed inputs, typed output, permission and bounded execution.

## Deliverable

Submit your changed experiment, redacted actual output, and a short explanation of what remains untested. Never include credentials. Reset by deleting only your own temporary output/virtual environment; do not delete repository fixtures.

## Acceptance rubric

Only BOOK/PEN and the exact sku field are accepted. Tool schema declarations are not sufficient; execute_tool repeats the validation at runtime.

Run `python3 -m unittest discover -s tests -p test_stages_02_04.py -v`. Fixtures are labelled synthetic; live vendor/app setup and screenshots require separate actual execution. See `solutions/s04/s04-l09.md` after attempting the task.
