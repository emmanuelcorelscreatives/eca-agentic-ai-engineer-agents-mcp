# s04-l02: Configure Multiple Model Providers

Build a configuration layer that can select providers and models without rewriting application logic.

## Run and inspect

From repository root: `python3 examples/stages02-04/foundations.py`. On Windows use `py -3` when appropriate. Inspect `FakeModel, CompatibleModel, OllamaModel` in `examples/stages02-04/foundations.py` (SDK class in `sdk_adapter.py`).

Instantiate two fixture models implementing chat and pass each into text_call without changing workflow code. Inspect providers.example.json and configure explicit model/endpoint values for a later real run.

## Deliverable

Submit your changed experiment, redacted actual output, and a short explanation of what remains untested. Never include credentials. Reset by deleting only your own temporary output/virtual environment; do not delete repository fixtures.

## Configuration-driven provider selection (semantic repair)

Use `provider_factory`/`load_provider_settings` in `examples/stages02-04/stage04_selection.py`; these supersede manually swapping fixture classes for this exercise. Declare named configurations:

```json
{
  "hosted": {"provider":"hosted_compatible", "model":"YOUR_AVAILABLE_MODEL", "base_url":"https://YOUR_AUTHORIZED_ENDPOINT/v1", "credential_env":"ACADEMY_MODEL_KEY"},
  "local": {"provider":"ollama", "model":"YOUR_ACTUALLY_PULLED_MODEL", "base_url":"http://127.0.0.1:11434"}
}
```

Load the private credential from the process environment mapping, select a name and call the returned client's common `chat(messages)` interface. Construction validates options/model/base URL but makes no request. `allow_live=False` is the default; actual requests require explicit opt-in. Only the selected hosted configuration needs its credential, so selecting local does not require a hosted account. All configuration schemas are still validated; unsupported providers/options and embedded credentials fail. Native Ollama uses its actual `/api/chat` service root and supports text only here; it does not silently accept OpenAI tool payloads.

The authored tests inject both real adapter transports with synthetic responses; they do **not** establish that either configured endpoint/model actually works. Retain genuine redacted responses from both selected providers before claiming a two-provider live demonstration. Do not put private credentials into the JSON, screenshots or transcripts.
