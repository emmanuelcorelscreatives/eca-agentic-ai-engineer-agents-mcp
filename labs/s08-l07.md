# s08-l07: Create Email Drafting and Delivery Tools

Build separate tools for creating drafts, previewing messages and submitting approved emails.

## Practical

Preview draft then request delivery with and without approval.

Read `projects/02-sales-team/sales.py` and its project README. Use synthetic fixtures only. Run `python3 -m unittest discover -s tests -p test_stages_05_08.py -v` and the project CLI. Distinguish offline observations from live SDK/browser/deployment work; do not claim unexecuted outcomes.

## Acceptance

Unapproved delivery fails. Approved local simulation adds one unique outbox row; live=True always refuses.

Record the actual command, observed output and any unmet named application requirement.

## Required actual transport exercise

Use `preview` before approval. Configure `OwnedSinkSMTP` for a newly owned loopback sink only. Approve its exact recipient/subject/body/revision hash, submit once, then inspect actual captured MIME and envelope identity. Compare decoded canonical body with preview text, Message-ID, revision header and payload hash. Prove unapproved/duplicate submissions fail and a forced timeout leaves a durable unknown outcome rather than retrying. `deliver()` is a simulated legacy exercise and cannot satisfy this lesson's actual SMTP objective.
