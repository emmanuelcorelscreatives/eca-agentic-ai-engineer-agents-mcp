# s21-l05: Work with Sessions and Agent State

Preserve conversation and application data across multiple agent interactions.
The same Academy inventory from Stage21 remains the task: ECA-KEY-01 is product
P-KEY, and ECA-MOUSE-02 is P-MOUSE. Stage22 policies cover these same products.

## Core exercise

Read examples/s21_state.py. set_preference writes selected_sku and
 delivery_preference through actual ADK ToolContext.state; get_preference reads
those session-scoped keys. They are registered on the actual ADK agent in
examples/s21_adk.py, including its MCP branch. No user:/app: prefix broadens their
scope. Invalid products and delivery preferences do not change saved state.

Run the genuine Runner three-turn source with an explicitly authorized provider
budget and configured GOOGLE_MODEL/provider credentials:

```sh
python3 -m examples.s21_state --database /tmp/academy-adk-sessions.db --live-model-turns
```

Turn1 of shopping-a asks the agent to save a keyboard/collection preference;
turn2 reads it back. shopping-b has no preference. Retain the actual event
stream and state. This authored sequence is not a claim that those runs passed.
The PDF essential is multi-interaction state/conversation, not a particular
SQL database or cloud service.

## Optional durable extension

DatabaseSessionService uses actual SQLite with aiosqlite. A provider-free
state_delta storage probe can run in separate processes:

```sh
python3 -m examples.s21_state --database /tmp/academy-adk-sessions.db --session restart-a --write
python3 -m examples.s21_state --database /tmp/academy-adk-sessions.db --session restart-a
```
