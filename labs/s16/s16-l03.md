# s16-l03: Invoke and Stream Model Responses

Execute standard and streaming model calls and process the resulting message objects.

## Coherent course case and actual source

Read `examples/s16/native_features.py` → `invoke_and_stream`. These are source references, not evidence that the new feature has passed runtime verification.

## Practical exercise

Invoke a configured model once, consume a separate native stream and inspect AIMessage/AIMessageChunk objects, including empty chunks and an interrupted stream.

## First run

Prepare the separate environment in the [stage guide](README.md). From the repository root, save and run this Python snippet in your exercise copy. It uses a deliberately scripted native SDK model, with no account or provider requests:

```python
from langchain_core.language_models.fake_chat_models import FakeListChatModel
from examples.s16.native_features import invoke_and_stream

model = FakeListChatModel(responses=["Synthetic fixture answer.", "Synthetic fixture stream."])
result = invoke_and_stream(model, "Read the synthetic Academy privacy page.")
print(type(result["invoked"]).__name__, result["invoked"].content)
print(type(result["streamed"]).__name__, result["streamed"].content)
```

Expected: an `AIMessage` for the first fixture answer and an `AIMessageChunk` containing the accumulated second fixture string. Record the actual classes and contents; this is not evidence of model intelligence or grounding.

For the optional real-provider comparison, configure `OPENAI_API_KEY` privately and choose an available model in `ACADEMY_MODEL`. Replace only the fixture construction above with the following. Calling `invoke_and_stream` then makes **two separate potentially billable requests**, one invoke and one stream; do not run it unless you intend that experiment:

```python
import os
from langchain_openai import ChatOpenAI

model = ChatOpenAI(model=os.environ["ACADEMY_MODEL"], max_retries=0, timeout=30, max_tokens=128)
```

Never print the key or assume a `.env` file is automatically loaded. Missing credentials, an unavailable model or an interrupted stream are real failures to retain, not reasons to substitute fixture text as a provider response.

## Acceptance and reference reasoning

Native invocation and streaming are separate requests; stochastic text need not match. Chunk addition preserves SDK message semantics. A raised stream propagates failure and an empty stream fails; no invented universal provider done flag is used. The older aggregate_stream helper is only a custom-format fixture.
