# s25-l08: Build the Test Generation Agent

Generate unit, integration and behavioral tests from the project’s acceptance criteria.

## Coherent practical case

A typed Academy catalog-research/draft-notification agent specification. Generated requirements, architecture, tools, instructions, tests and reviews must feed the same approved dependency graph and produce a real runnable selected-framework project.

## Source map

Project root: `projects/07-agent-factory`. Baseline source anchors: `advanced.py: test_trusted_template; generated test artifacts`. Read the current integrated module listed in the stage workbook as well; baseline helpers alone do not prove full application integration.

## Exercise

Generate unit, integration and behavioral tests linked to each approved acceptance criterion. Seed a requirement defect and verify tests detect it.

## Acceptance and reasoning

The independent acceptance suite is not writable by the generator or repair loop. Generated tests must be reviewed for criterion coverage and actually executed only in the authorized sandbox. Fixed tests for two templates alone do not establish a general test-generation stage.

## Verify your result

Record the command, dependency versions and actual result when you run this exercise. Expected results are not observations. Offline fixtures, SDK construction, model responses, browser interactions and Docker execution verify different things; report skips and failures honestly.

## Current generative implementation

Read `projects/07-agent-factory/` → `model_pipeline.py: Pipeline.generate stage tests, prepare_workspace; model_schemas.py: ArtifactProposal`.

Generated tests are additional artifacts. The trusted orchestrator supplies an independent acceptance suite before generation under acceptance/; the model and repair stages cannot rewrite it. Retain criterion coverage and actual test evidence separately.
