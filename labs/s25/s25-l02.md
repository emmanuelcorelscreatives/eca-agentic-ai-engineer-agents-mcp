# s25-l02: Define the Typed Agent Specification

Create a schema describing purpose, users, tools, data, outputs, policies and deployment requirements.

## Coherent practical case

A typed Academy catalog-research/draft-notification agent specification. Generated requirements, architecture, tools, instructions, tests and reviews must feed the same approved dependency graph and produce a real runnable selected-framework project.

## Source map

Project root: `projects/07-agent-factory`. Baseline source anchors: `advanced.py: TypedSpec, example_spec`. Read the current integrated module listed in the stage workbook as well; baseline helpers alone do not prove full application integration.

## Exercise

Inspect and validate purpose, users, tools, input/output schemas, data, policies, secrets and deployment requirements. Try malformed and forbidden variants.

## Acceptance and reasoning

The canonical spec must be strict, bounded and stable enough to hash. Environment variable names are configuration, never secret values. Unsupported tools/framework capabilities fail explicitly. Every downstream stage binds the same approved specification digest.

## Verify your result

Record the command, dependency versions and actual result when you run this exercise. Expected results are not observations. Offline fixtures, SDK construction, model responses, browser interactions and Docker execution verify different things; report skips and failures honestly.
