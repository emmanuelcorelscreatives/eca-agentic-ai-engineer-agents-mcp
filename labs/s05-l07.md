# s05-l07: Handle Multiple Tool Calls

Process several tool requests safely within a single agent turn using an explicit tool registry.

## Authoritative implementation

Use `ToolsService.run` in `projects/01-digital-twin/tools.py` and the persistent `SQLiteStore` in `storage.py`. This is the bounded, call-ID-aware, replay-safe registry. The retained `twin.py/run_tools` comparison returns ordered introductory outcomes but does not implement these durable guarantees.

This exercise supplies one **manual synthetic registry turn**. The source of requests and their safe processing are separate concepts. No actual model-generated multi-tool turn or SDK-output bridge has been observed, and none is implied by this lab.

## Practical

Create a private file-backed database and a batch of at most eight calls: a valid `record_lead`, an unknown tool, and a valid `capture_question`. Give each call a unique stable `call_id`, provide explicit consent and retain the returned ordered outcomes.

1. Close `ToolsService`, reopen the same database, then submit the exact successful IDs and payloads again. Compare receipts and record counts; no second lead/question/outbox may appear.
2. Reuse the lead call ID with a different email or tool name. Expect rejection while the original receipt remains unchanged.
3. Submit a nine-call batch. The turn bound must reject the batch before the first write.
4. Inspect a mixed failure/success batch. A rejected call must not claim another action failed or succeeded; each outcome retains its own call ID.
5. Examine retention tombstones: a retired call ID must not recreate erased personal data through replay.

Use `ToolCall(name, args, call_id)` or the documented equivalent object shape; do not omit IDs and fall back to the legacy method. Relevant checks are `tests/test_stage05_semantic_repairs_tools.py`.

## Acceptance

Execution order and individual outcomes match the submitted manual turn. Exact successful replay returns the same receipt after service restart. Changed arguments with an existing ID are refused. The eight-call bound, atomic writes and retained history all belong to `ToolsService`, not the old introductory API. Record actual commands and observed output; do not present a manual turn as autonomous model behaviour.
