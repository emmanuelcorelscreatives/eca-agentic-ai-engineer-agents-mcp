# s02-l09: Handle API Errors, Rate Limits and Invalid Responses

Add exception handling, retries and validation so model integrations fail predictably and recover safely.

Inject two explicit RateLimited failures then a success; supply a list.append fake sleeper. Separately inject TimeoutError, bad authentication and invalid JSON/content at the boundary. Do not retry an ambiguous transport outcome.

## Acceptance rubric

Recorded backoff delays are [1,2], maximum attempts three. Non-RateLimited errors escape immediately. Inject a zero-jitter callable to reproduce [1,2]; the default adds 0–0.25 seconds of jitter. A fake clock tests elapsed retry admission without sleeping. Each operation still needs its own transport timeout.

Run `python3 -m unittest discover -s tests -p test_stages_02_04.py -v`. Fixtures are labelled synthetic; live vendor/app setup and screenshots require separate actual execution. See `solutions/s02/s02-l09.md` after attempting the task.

## Real adapter classification, injected offline

Use `ObservedCompatibleModel`, `ModelBoundaryError`, `retry_after_seconds` and `qualified_retry` in `stage02_configuration.py`. Inject real urllib HTTPError instances through the transport seam: 429 maps to rate_limited with sanitized request ID and Retry-After, 401/403 to terminal authentication, 400/404/422 to invalid_input, other HTTP failures to no-auto-retry, malformed envelopes to invalid_response, and timeout/connection failures to remote_outcome_unknown. Raw provider error bodies and headers never become user-facing exception text.

Only explicit 429 is retry eligible under this teaching policy; obey the greater of backoff and Retry-After within attempt/elapsed admission caps. A long hint causes a stop, not a shortened forbidden retry. The operation retains its own transport timeout. Missing/invalid structured requirements are rejected by `validate_requirements`. Do not generate paid failures or replay an unknown timeout to demonstrate these cases; the authored injected-HTTP tests cover this offline.
