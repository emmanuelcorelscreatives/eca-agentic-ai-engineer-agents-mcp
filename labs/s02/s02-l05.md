# s02-l05: API Keys, Environment Variables and .env Files

Store and load credentials securely without exposing secrets in application code or version control.

## Run and inspect

From repository root: `python3 examples/stages02-04/foundations.py`. On Windows use `py -3` when appropriate. Inspect `api_key` in `examples/stages02-04/foundations.py` (SDK class in `sdk_adapter.py`).

Copy data/s02/.env.example into an ignored local .env only if you deliberately configure a dotenv loader; otherwise set MODEL_API_KEY in the process environment. Test a missing value and a placeholder with api_key, then a synthetic sentinel. Inspect what would be tracked before committing.

## Deliverable

Submit your changed experiment, redacted actual output, and a short explanation of what remains untested. Never include credentials. Reset by deleting only your own temporary output/virtual environment; do not delete repository fixtures.

## Acceptance rubric

api_key rejects missing/placeholder values with a generic message and returns a valid value without printing it. The example does not auto-load .env. Delete the local test secret after the exercise.

Run `python3 -m unittest discover -s tests -p test_stages_02_04.py -v`. Fixtures are labelled synthetic; live vendor/app setup and screenshots require separate actual execution. See `solutions/s02/s02-l05.md` after attempting the task.

## Explicit runnable configuration boundary

Use `load_configuration` from `examples/stages02-04/stage02_configuration.py`. Copy **`data/s02/.env.example`** into an ignored local `.env`, replace the placeholder with a dummy sentinel, and choose a synthetic model name for offline inspection. Call `load_configuration('.env', env={})` explicitly: nothing auto-loads at import time. The returned `Configuration` hides its credential from repr. Do not print `.api_key`.

This loader accepts literal KEY=value lines, blank lines, comments and simple whole-value quotes. It intentionally rejects interpolation, shell syntax, unknown/duplicate keys and conflicting aliases. Process variables override file values. Standard names are MODEL_API_KEY/MODEL_NAME/MODEL_BASE_URL; the root OPENAI_API_KEY/OPENAI_MODEL aliases are accepted only when they do not conflict. Never silently mix two credentials.

Inspect the authored tests in `tests/test_stage02_semantic_repairs.py`: temp files use synthetic sentinels; stdout/stderr/exception text and repr must exclude them. `placeholder_tracking_check` reports ignore declarations only. Actual `git check-ignore .env`, `git ls-files .env` and staged-name inspection must be performed in the disposable learner repository; a declaration is not proof that a previously tracked secret was removed.
