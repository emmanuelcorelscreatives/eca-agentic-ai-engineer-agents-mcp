## Complete setup and source-control route (semantic repair)

This route supersedes the earlier suggestion that an unpinned optional `pip install` is a reproducible environment. Commands below are learner actions, **not retained execution receipts**. Use a disposable personal exercise directory/repository, not the Academy production checkout. Install Python, uv and Git from their official sources; verify actual versions first.

1. Clone the Academy repository into your exercise directory. In that clone, `uv sync --no-install-project --python 3.12` resolves the actual project metadata and creates an actual `uv.lock`/virtual environment. Run `uv run --no-sync python -c "import platform,sys; print(platform.python_version()); print(sys.executable)"`. Record the exact printed Python version, then run `uv python pin EXACT_PRINTED_VERSION`, replacing the argument with the observed version. Rerun sync. Do not handwrite a fictitious lockfile.
2. Run `uv run --no-sync python examples/stages02-04/foundations.py` and `uv run --no-sync python -m unittest discover -s tests -p test_stages_02_04.py -v`. The core is stdlib-only; no model credential is needed. Save the actual outputs privately with tool versions.
3. Optional SDK track, on your exercise branch only: `uv add --optional model openai`, then `uv sync --extra model --no-install-project`. Inspect the version resolved in your actual lock and retain it; this course does not claim an SDK version was installed here. Commit the real changed metadata and lock together. Future installs use `uv sync --frozen --extra model --no-install-project`.
4. Create an empty authorized personal GitHub exercise repository. In a separate local copy without the Academy Git history, `git init`, `git branch -M main`, `git status --short`, `git add .`, then inspect `git diff --cached --name-only`. Confirm no populated `.env`, credentials or personal artifacts are staged. Only then `git commit -m "Add reproducible Academy exercise"`, `git remote add origin YOUR_AUTHORIZED_REPOSITORY_URL`, and `git push -u origin main`. Configure your own Git identity if needed; do not copy an instructor identity.
5. In a new empty directory, `git clone YOUR_AUTHORIZED_REPOSITORY_URL exercise-check`, enter it, then `uv sync --frozen --no-install-project` (add `--extra model` for your optional SDK track). Rerun the same demo/tests and compare actual output. Record clone revision using `git rev-parse HEAD`, Python/uv versions and exit statuses. No live request follows automatically.

A lockfile pins resolved package versions; it does not pin OS drivers, guarantee every platform, or prove optional SDK API compatibility. The exact Python/OS/uv versions and real fresh-clone execution still need their own receipts. A successful existing Academy CI run is not your personal GitHub push demonstration.
