# Practice guide

Start with the [repository setup](../README.md#start-locally). Run commands from the repository root unless a project README explicitly changes directory. No API account is needed for the eight deterministic reference demos.

## Work through a lesson

1. Find the lesson ID in the [curriculum guide](../curriculum/README.md) and its workbook: [stages 1–10](../curriculum/workbooks/stages-01-10.md), [11–20](../curriculum/workbooks/stages-11-20.md), or [21–30](../curriculum/workbooks/stages-21-30.md).
2. Read the objective, practical task, deliverable and acceptance criteria. Use the [material index](../curriculum/materials.json) to find supplied labs, data and reference solutions.
3. Run the corresponding project demo and tests before modifying a private exercise copy. Observe what the starter actually implements.
4. Attempt the exercise before reading its solution. Write down the expected result, then run your change and separately record the actual result, including failures and skipped integrations.
5. Compare your submission with the [completion rubric](../curriculum/completion-rubric.md). A fixture pass does not complete a lesson requiring a real configured model, browser, framework or deployment.

## Keep practice safe

Use fictional course fixtures or data you explicitly intend to share. Never commit keys, personal documents, customer data, browser profiles or private execution traces. The sales project defaults to drafts/simulation, browser actions remain bounded and approval-controlled, generated code needs real isolation, and the trading project is paper-only. Read each application's boundaries before enabling optional integrations.

Install optional frameworks in separate environments. Review account permissions, current provider costs and a small explicit budget before making live calls. Missing dependencies are reported as skips, not successful integrations. See [recording results](../evidence/README.md) for a useful experiment log format.
