# One concrete practical, separate extensions

Stages 11–12 use **Academy Market Debate**, asking whether fictional Alder Retail should launch a capped second-region delivery pilot. Runtime input is a validated fixture **topic**, not a company symbol. The roles are advocate, skeptic and reviewer. Support precedes challenge, and verdict receives both.

The CLI-generated `academy_practice` directory is a starter example; the supplied `academy_market_debate` package is the debate implementation. Compare their names and structure rather than treating the generated default crew as this application or as evidence that the debate ran.

The workbook follows these debate roles and the `--facts` input through stages 11–12. Stage 13 develops the [market-company screener](../../README.md) with company profiles and researcher, analyst, screener and reviewer roles. It is an extension in the same course project, not a new set of accepted inputs or role names for the debate. Follow the [advanced handbook](../../advanced/HANDBOOK.md) for the screening and company/sector research exercises.

The [external-document research variant](s12-l05.md) uses real official framework documents. It never substitutes those documents for fictional retailer evidence. The [optional memory variant](s12-l10.md) is configured for CrewAI storage/recall with approved scoped facts; the ordinary stage-11 debate remains memory-disabled by default.

One actual bounded debate can support stages 11 lessons 8 and 10 when its task outputs and trace satisfy both acceptance criteria. Offline configuration, manual argument drafting and constructor checks are useful exercises, but do not prove model execution. Process comparisons and memory retrieval need their own actual observations; missing access or an unknown outcome remains incomplete, not an expected result to invent.
