# Completion rubric

Track **watched**, **practiced**, **tested** and **submitted** separately. Watching a demonstration alone does not establish practical competence. This rubric is an assessment guide, not an accreditation or employment guarantee.

For every portfolio project submit a README linking its exact curriculum project ID, requirements, inputs and limitations; reproducible setup with versions; source and non-secret configuration; synthetic/public data provenance; actual test commands and retained output; and a demonstration trace or genuine application captures. Clearly distinguish fixture/simulated runs from genuine model-enabled and deployed runs. Record a failure honestly rather than manufacturing a successful observation.

| Criterion | 0: missing | 1: developing | 2: satisfactory |
|---|---|---|---|
| Scope and coherence | No defined user/output | Partly mapped | User, inputs, outputs and exclusions agree with curriculum |
| Reproducibility | Cannot run | Manual gaps | Fresh setup and documented commands reproduce observations |
| Functional behavior | Claimed only | Happy path only | Real happy path and relevant failure cases retained |
| Evidence and grounding | Unsupported assertions | Partial provenance | Exact source/data/run trace supports each claimed result |
| Controls | Unbounded actions/secrets | Some boundaries | Least-privilege tools, validation and required human approvals |
| Evaluation | No tests | Only generated assertions | Tests check meaningful outcomes and limitations are explicit |
| Communication | Unclear handoff | Basic description | Concise demonstration, known failures and maintenance notes |

A project is **submission-ready** only when all seven criteria score 2, no unresolved secret exposure or unauthorized external action exists, and an independent reader can reproduce the required practical. Scores do not replace the lesson-specific acceptance criteria. A failed or unexecuted live-model requirement stays pending even if offline fixtures pass.

For P02 retain approval before outreach delivery; P06 retain approval for sensitive browser actions; P08 is paper-only. Never put keys or private customer/student records in a public repository. Eight-project completion requires eight separately evidenced submissions; the introductory preview does not mark any complete.
