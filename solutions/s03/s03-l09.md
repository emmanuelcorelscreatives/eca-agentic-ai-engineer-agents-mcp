# Solution notes: s03-l09

Reference implementation: `execute_tool, agent_loop` in `examples/stages02-04/foundations.py`; optional SDK implementation in the adjacent `sdk_adapter.py`.

Unknown tools, extra arguments and repeated IDs fail. Treating content as data reduces privileges but does not solve semantic prompt injection; consequential actions need a separate permission/approval boundary.

The full offline demo is reproducible with standard-library Python. The dedicated tests exercise success and negative boundaries; their PASS proves those code paths, not live model quality, named application installation or screenshot approval. Preserve this distinction in your submission.

Suggested discussion: Try an unknown delete tool, an extra shell argument, a repeated tool-call ID and a response containing prompt-injection text. Identify what allowlisting blocks and what it cannot prove.
