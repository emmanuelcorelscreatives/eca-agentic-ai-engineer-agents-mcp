# s06-l09: reference reasoning

Separate process seed/followup/control invocations prevent an in-memory object from
masquerading as restart persistence. The real SDK Runner synthetic-model probe
checks marker delivery through the SDK's own SQLite schema. Live dialogue uses
the same session route with an authorized model, but its intelligence and answers
cannot be inferred from the synthetic persistence contract.

An in-memory SQLite default is not durable across processes. db_path selects durable storage, session_id selects history. The test reopens the actual SDK session and clears only its selected history.

Inspect `SQLiteHistory / SQLiteSession` in `examples/stages06-07/`. Validate using `test_actual_sdk_sqlite_session_restart_and_isolation` in `tests/test_stages_06_07.py`.

Do not copy expected output as observed evidence. Retain an actual run log and explain any failure. Offline test success proves application boundaries and deterministic behavior; it does not establish model accuracy, latency, token usage or hosted trace availability.
