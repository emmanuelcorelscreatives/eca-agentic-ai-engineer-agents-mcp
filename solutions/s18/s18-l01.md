## Required behavior and explanation

The native message field uses add_messages. Stable message IDs distinguish updating/replacing a message from appending a new turn. The actual graph receives prior thread state on later invocations; the custom Sessions list store is supporting infrastructure, not proof of native reducer behavior.

## Reproduction task

Append two conversation turns through native graph state and explicitly replace an earlier message by its ID.

## Message replacement is not privacy erasure

Replacing a message updates that exact message ID through the native add_messages reducer. It does not erase older assistant replies that may quote the original text, and historical checkpoints can still retain that text. This exercise demonstrates a specific message update, not full-history forgetting or privacy erasure. Any deletion/retention promise needs a separate explicit design and verified storage policy.
