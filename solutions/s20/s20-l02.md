# Reference answer: s20-l02

Project root: `projects/06-browser-sidekick`. Baseline source anchors: `advanced.py: Plan, parse_model_plan`. Read the current integrated module listed in the stage workbook as well; baseline helpers alone do not prove full application integration.

## Required implementation reasoning

A fixed fixture_plan is a labeled test double. The actual objective must reach the model-backed planner and its structured output must pass the real plan validator before persistence. Unknown tools, off-origin targets, oversized plans and cyclic or missing dependencies fail. A model proposal never grants permission to execute.

## Reproduce and inspect

Submit two different objectives to the configured planner and inspect ordered steps, dependencies, tool requirements and measurable completion criteria.

## Evidence boundary

Record the command, dependency versions and actual result when you run this exercise. Expected results are not observations. Offline fixtures, SDK construction, model responses, browser interactions and Docker execution verify different things; report skips and failures honestly.

## Integrated application source

Read `projects/06-browser-sidekick/pipeline.py` → `NativePlanner.plan; SidekickApplication.create, create_from_plan` (references prefixed advanced or ui_gradio name their neighboring module).

NativePlanner invokes the actual Deep Agents coordinator and scoped native specialists, then validates the final plan. FixturePlanner is explicitly deterministic and never an AI observation. create reserves a durable planning intent before a model submission; an unresolved prior intent is not resubmitted automatically.

The integration source is a starting point. Verify the configured model, specialists, browser and interface separately; their presence in source is not a successful runtime result.
